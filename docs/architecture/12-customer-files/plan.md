### 第 0 步 · 开工核对与实测（2026-10-29，协调者）

- **行号核对**：spec 引用的 22 处源码行号都在文件范围内；spec 翻 `ready`（`5a1c6905`）之后 `src`、`eval` 没有新提交，引用照旧有效。基准为 dev `fce0803c`。
- **企微实测**（工业演示账号；owner 用手机发合成样本）：
  - 怎么跑：owner 当次授权，改由协调者在线上 app 容器内跑一次性只读脚本。脚本用应用自己的解密路径取凭据，调 `kf/sync_msg` 与 `media/get`。只打印消息类型、字节数、响应头名、魔数、扩展名与文件名长度；凭据、企微标识、文件名全文都不打印。跑完即删。
  - 结果：

    | 样本                 | 消息类型 | `media/get`  | Content-Type               |  实收字节 | 文件名               |
    | -------------------- | -------- | ------------ | -------------------------- | --------: | -------------------- |
    | 01 清单截图（PNG）   | image    | 200 · 0.2 秒 | `image/png`                |    53,704 | 企微生成，91 字      |
    | 02 手写清单（JPEG）  | image    | 200 · 0.1 秒 | `image/jpeg`               |    40,066 | 同上                 |
    | 03 铭牌（JPEG）      | image    | 200 · 0.1 秒 | `image/jpeg`               |    48,992 | 同上                 |
    | 10 大图（PNG）       | image    | 200 · 0.4 秒 | `image/png`                | 5,208,002 | 同上                 |
    | 05 询价单（XLSX）    | file     | 200 · 0.1 秒 | `application/octet-stream` |     2,816 | 原文件名             |
    | 06 询价单（GB18030） | file     | 200 · 0.1 秒 | `application/octet-stream` |        86 | 原文件名             |
    | 09 图纸（PDF）       | file     | 200 · 0.1 秒 | `application/octet-stream` |       603 | 原文件名             |
    | 11 超大文件（21 MB） | text     | —            | —                          |         — | 消息正文就是原文件名 |

  - 结论：
    - 消息体里只有 `media_id`，没有名称、大小、类型字段，一切靠 `media/get` 的响应头和内容。
    - 实收字节与本机样本逐个相等，魔数一致：原样到达，图片没有被转码或压缩。
    - 5.2 MB 的图片照常到达，企微没有按 2 MB 拦图片。
    - 响应头有 `Content-Length`，读正文之前就能判超限；文件消息的 `Content-Type` 一律是 `octet-stream`，判类只能靠魔数与扩展名。
    - 文件消息的 `Content-Disposition` 带原文件名；图片消息的名字由企微生成，没有意义。
    - 超过 20 MB 的文件不会以文件消息到达，企微改发一条客户文字消息，正文就是原文件名。
