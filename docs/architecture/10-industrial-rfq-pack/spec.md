**一句话：** 用 08 的通用形状与 09 的报价审批，做第二个真实行业包「工业品询价」，并在同一部署里开一个演示租户。客户在企业微信或网页里发来型号和数量，常常一次十几行、写法五花八门。AI 先把型号归一，在产品库里找到条目，按阶梯价和起订量试算，说清现货与交期；客户要正式报价时，AI 起草报价单，顾问批准后，系统把报价单链接发给客户。非标、来图加工、账期、样品、超长询价转人工。价格只由代码算；库存、交期、替代只说工具查到的；型号只说产品库里有的。数据全部是合成的。

## 背景与问题

- 08 与 09 给出了通用形状与报价审批，但只有证明包在用，没有真实的第二个包。主参考说过：第二个真实行业包跑通之前，「通用」只是设计主张。
- 询价场景和定制游差别很大，正好检验模板的边界：
  - 单价低、带小数，按数量分档，有起订量；
  - 一次询多行，型号写法不统一（`6205-2RS`、`6205 2rs`、`6205RS`）；
  - 库存和交期每天在变；
  - 有一部分需求系统兑现不了：非标、来图加工、账期、样品。
- 旅游的 `HandoffVocab` 有 104 个键，其中不少是旅游语义（高反、行程变更等）。
- 演示租户会让部署从「一个 standard 租户」变成「两个」。这时公开路由改为严格按 Host 匹配：每个租户都要有 `public_host`，宿主的 `PUBLIC_BASE_URL` 要与它一致（`src/tenancy/hosts.ts:30-45、65-71`）。

## 目标

1. **工业品询价包 `industrial`。** 公开参考包，用合成数据。内容包括：
   - 产品种类 `part`，可用 CSV 导入；
   - 型号归一与匹配；
   - 确定性定价；
   - 四个工具；
   - 护栏：库存与交期、替代、税票、价格承诺、型号、金额；
   - 确定性转人工与客户确认；
   - SOP、policy、品牌、词表、跟进、洞察、mock、后台配置。
2. **演示租户 `industrial-demo`。** 同一部署里另开一个，用自己的域名和网页渠道，有约 40 条合成产品。
3. **评测。** 工业包的模拟客户目标进发布闸；cases v2 回归随 `pnpm test` 跑。
4. **旅游不变。**

## 非目标

- 外部业务系统连接器（11，第一家 Odoo）：本 spec 的库存与交期由商家在产品库里维护。
- 客户发来的图片与文件（12）：本 spec 只处理文字消息，包括一次粘贴多行。
- 体验页 `/try` 的工业包模板（沙箱多模板）。
- 开发票、合同、物流跟踪；多币种；英文。
- 仓库里放任何真实厂商的手册、价格或品牌（ADR-003）。
- 产品条目下架；沿用现行契约，active 不能回到 draft。

### 工具定义（摘要）


### 建单拒绝结果的投影（R5）

以 `src/core/order-view.ts:128-173` 的拒绝集合为准，保持核心返回的顺序、每行 code 与 reason；不把部分成功行建成报价，不因拒绝写入新报价、推进 lastQuoteId 或发审批通知。`kind` 仅在核心内部使用，工具入参仍只有 code / qty，不新增 kind 参数。

| 核心拒绝原因    | 工具返回的单项（外层统一为 `{ rejected: [...] }`） | 含义与边界                                                             |
| --------------- | -------------------------------------------------- | ---------------------------------------------------------------------- |
| `empty_lines`   | `{ code: '', reason: 'empty_lines' }`              | 空行集；保留核心的空编号哨兵，不带 moq                                 |
| `kind_unknown`  | `{ code, reason: 'kind_unknown' }`                 | 未登记种类；工业工具固定补 part，映射自测注入核心结果，不让客户选 kind |
| `item_inactive` | `{ code, reason: 'item_inactive' }`                | 当前上架快照找不到条目（不存在或仍为草稿），不带 moq                   |
| `invalid_qty`   | `{ code, reason: 'invalid_qty' }`                  | 非整数、少于 1 或超过 maxQty，不带 moq                                 |
| `below_moq`     | `{ code, reason: 'below_moq', moq: detail.moq }`   | R4 的包级拒绝；moq 必须是合法正整数，只取该字段，不透传整个 detail     |

核心还允许 `priceLine.reject` 为其他字符串，但工业包本期只返回 below_moq；以后新增原因须同步显式映射。遇到未知原因、below_moq 缺少合法 moq 或核心抛出配置 / 金额异常时，走既有工具失败处理，不漏掉该行、伪装成功或冒充 below_moq，不把内部异常 / detail 透给客户。验收覆盖全部五种原因、混合拒绝与异常防误报。

- **跟进链接**：两个工厂共用只需要 `text` / `session` 的删除逻辑，各自用上下文已有的 `recordGuard` 记 `link_whitelist`；返回 pass 或 strip，跟进不依赖主回复专属字段、不强转成 `ReplyGuardContext`。删空交 R14 新增的核心空串分支与两条调度适配跳过发送，不再宣称现有逻辑会跳过；不得补固定句或调用工具。主回复输出与 guard 记录逐字节回归。
- **跟进生成与发送契约**：`followUpText(session): Promise<string>` 签名不变；R8 启用条件成立时，完整 URL 先交白名单，护栏删空返回 `''`。`runFollowUpScan` / 数据库任务执行体收到空白后都在额度预占与跟进记账前跳过；数据库任务用现有 cancelled 结果承载 guard_empty，不改任务状态枚举。未启用的旅游分支维持订单号清洗、模板与发送计数旧语义。
- **确认候选选择**：同一 now 下仅选 quoteState 为 pending / approved / expired 的可读本会话报价，再与 rfqDraft 合并；比较键为事件时间、同时间草稿优先、订单 createdAt、订单 id，均按 R11 固定顺序。只用选中项的 quoteState 决定确认 / 待审提示 / 过期说明，终态不触发确认通知或 confirmedQuoteAt 更新。
- **状态容量**：`rfqDraft` 的 exact 行必须同时有合法 code / version，其他匹配类型均不带；版本为正安全整数，数量为正安全整数（超过 R4 上限仍拒绝定价），时间为非负安全整数。连同合法 `lastQuoteId`、`confirmedQuoteAt`，30 行最坏长度也须经测试证明 ≤ 6,144 字节；完整状态再按 R7 淘汰缓存至 ≤ 8,192 字节。版本读取不到时不编造型号、也不放宽任何护栏；R6 的当前库存条件仍需实际读取成功。
- **模拟种子**：审批种子只供声明 `quotes` 的包使用；pending 只搭配 `status: 'pending_payment'`，approved 可搭配现有状态。毫秒时间戳须为非负安全整数；`requestedAt <= 模拟当前时间`，approved 另满足 `requestedAt <= decidedAt <= 模拟当前时间`。目标中的绝对时间以 `FIXTURE_CLOCK` 为基准写，过期样例按 `quoteValidUntil` 的自然日边界留足余量，不依赖真实日期；不另加 per-goal 时钟。初始化不触发通知，旧种子与现有单槽校验保持不变。

1. **旅游不变。** 照 08 验收 1、09 验收 1。
2. **产品库。** 演示租户：

   - 草稿里替代型号找不到、型号与别人重复，照样能保存；上架与编辑 active 时以 422 点名冲突字段；跨条目钩子只在这两种写路径调用。没有下架入口，active → draft 无论是否被替代引用都由既有状态规则拒绝，不增加引用方特例；

3. **匹配。** 自测覆盖 R3 的每条规则：`6205 2rs` 精确命中 `6205-2RS`；`6205` 返回同系列候选，排序符合 R3；`M8x30`、`M8*30`、`M8×30` 归一后相同；不足 4 位的前缀不算同系列；按名称问（「25 内径的深沟球轴承」）时走知识库召回，命中对应条目；库里没有的型号返回 `none`；语义路径记录含 embedding 的端到端时延、样本量与环境，与内存性能分开报告。
4. **定价。** `priceLine` 的自测覆盖各档边界、起订量边界、库存三种情况；mock 对话里，`quote_items` 的逐行单价、行金额、合计与自测一致；低于起订量的那行没有价格，建报价单时被拒并说明起订量；按 R5 投影表逐一覆盖 empty_lines、kind_unknown、item_inactive、invalid_qty、below_moq：前四种无 moq，只有最后一种带合法 moq，混合拒绝保持全部行与顺序、整单不建单 / 不发通知；未知原因、缺失 moq 与异常不得误报成功或低于起订量。已装载 40 条产品时，以最多 30 行覆盖精确 / 别名 / 前缀路径，记录样本量与环境，匹配加定价 p95 ≤ 50 ms；知识库时延不混入。核对四个工具的声明与实际状态 / 通知写入，缓存和重试遵守接口表；跟进不能调用任一有副作用工具。
5. **护栏。** 每条规则都有正例与反例自测；mock 对话分别触发「编造现货」「编造替代」「编造型号」「不含税说成含税」「全网最低」，各自被删或被换，`guard_events` 有记录；规格写法不被误删；问句与条件句不动；15 个短询价行（前 10 行加补句本来就不超过 12 行 / 600 字，且没有额外超长保护句）经 `rfq_trim` 后只列 10 行并补「另外 5 行已算好」；长行样例触发二次删句，N 等于最终完全删掉的原始询价行数。同一原始行含多句不重复计数，部分保留不计删行；仅链接句 / 补句已超限、单个无句号长串、多行保护内容均终止并满足 12 行 / 600 非空白字符，必要时使用无链接 / 无 N 的固定兜底；跟进只删，删空不发送。链接跟进版覆盖同租户 / 同会话 / 批准且未过期放行，以及跨租户、其他会话、待审 / 过期 / 撤回、未登记、编码 / 穿越 / 外链删除；删除引导残句，记录 guard，无建单 / 转人工 / 通知，主回复工厂与旅游输出字节不变。跟进链接必须经真实 `followUpText → composeFollowUp → guardOutbound` 链路验收（只桩住 LLM 与发送端，不替换生成器 / 护栏）：合法已批报价 URL 的 ord_ 编号完整保留，非法链接在白名单处被删；旅游同输入仍按原法删除订单号，输出逐字节对照。

8. **跟进与会话状态。** 「报价」阶段空闲 24 小时：没有待审报价单时发提醒，有待审时不发；「促成」阶段空闲 24 小时发提醒；用注入的时钟验证。文件扫描与数据库任务分别以真实生成 / 护栏链路制造删空结果：push 调用为 0，无新增消息 / outbound_sends / 渠道 pending，不预占或消耗额度，count / stages / lastAt / pendingAt / failures 均不变；数据库任务 cancelled / guard_empty 且不立即重排，文件本轮跳过。合法报价链接的非空回复在两路都完整送出且只正常计一次；旅游删空后仍换原模板发出、计数与字节同基准。`resetSession` 之后，`packState` 的四项都被清掉；30 行摘要用最长合法编号 / 最大合法整数验证必留状态 ≤ 6,144 字节；长原查询、候选和规格不混入摘要。大量 / 单个超长缓存项按最旧优先整项淘汰，含 JSON 转义与多字节文本时完整状态始终 ≤ 8,192 字节。淘汰前后 R6 自动批准、R11 最新对象与确认结果一致，摘要行、match、版本与时间不丢不改；缓存删空也能按摘要版本识别询价型号，重置四键后不沿用旧状态。

## 被否决的方案

- **条目编号从型号推导。** `6205-2RS/C3` 与 `6205 2RS C3` 推出来是同一个编号，会撞号。改由商家给编号，型号另做唯一性检查。
- **阶梯价存子项。** 见开放问题 4。
- **型号护栏用「字母数字混合就算型号」的宽规则。** 会把 `25mm`、`IP65`、`G1/4` 这类规格写法一起删掉。改为排除规格与单位的写法，并把在场条目的规格词算作已知。
- **「过期后确认」走确定性回复。** 确定性回复做完就结束这一轮，没法接着试算。改为给模型写一条上下文说明，由它调 `quote_items`。
- **在仓库里放真实厂商的手册与价格。** 有版权问题，也违反 ADR-003。真实材料留给 12，只在本地处理，不入库。
