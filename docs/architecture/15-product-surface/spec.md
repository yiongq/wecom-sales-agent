## 目标与非目标

目标：官网、文档与双语 README 的对外主线只讲工业询价，用合成截图解释收询价、匹配产品、试算、报价审批与人工接手；文档提供六类工业询价使用指南；后台增加只读组织、成员、渠道与 14 用量页及新手清单；线上 prod、普通登录、一个共享试用账号；不换宿主，完成工业新旧地址切换和回退设计。平台仍以行业包支持多行业；旅游是第二个行业包与回归基线，不再加功能，代码与回归保留，不出现在对外主线。

非目标：网页邀请、角色修改、网页提交渠道、渠道热重载、在线修改组织；统一 SaaS 身份或自助注册；开通购买流程、自动收款、ERP 设置界面；后台视觉重做、模型或 SOP/护栏调整；prod 解禁网页渠道；仓库改名；宿主迁移、旅游新增功能或旅游对外推广。商业内容另记。

## 现状与方案

### R1 · 三个入口与静态托管

完整地址通过私有发布配置注入，公开文档只写子域职责。

| 子域   | 用途                                       | 边界                                                                                                                         |
| ------ | ------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| `www`  | 工业询价官网、能力、截图、隐私、条款与页脚 | 现有 Caddy 服务静态构建产物；不读成员 cookie、不请求租户 API                                                                 |
| `app`  | 正式登录及 `/console/` 后台                | 现有 Node 服务，经 Caddy；仅映射现有非宿主工业 standard 试用租户，其 public_host 改为 app；旅游保留宿主并停用，先按 R12 验证 |
| `docs` | 工业询价使用者文档                         | 同一 Caddy 的独立静态根；不发布架构、计划及运维材料                                                                          |

静态站选现有 Caddy：复用发布链，代价是共用服务器故障域；曾比较 Pages，独立发布有益但增加部署配置，后续仍可迁移相同产物。文档采用 VitePress，固定版本与锁文件，独立于 console 运行依赖。已定选型在实施第 1 步登记 ADR。

静态根只指构建产物；私有品牌、法律正文、实际地址与账号在仓库外组装。公开构建可用明确占位，正式发布检查拒绝缺项。后台沿用同源检查、CSP、no-store 与 Host-only cookie，不放宽跨源租户 API；新域首次登录，不能靠扩大 cookie Domain 迁移会话。未知 Host 在代理层拒绝，避免单租户时应用的默认 Host 回落成为公开入口。

### R2 · 官网与申请试用

新增静态源码 `site/`，不塞入客户页面目录 `public/`。固定页面 `/`、`/product/`、`/privacy/`、`/terms/`。首页展示「单来」的工业询价定位、合成产品截图、询价接收 → 产品匹配与试算 → 报价审批 → 人工接手的流程、文档与后台入口；不登录也能看懂。官网主线不展示旅游接待、行程或旅游支付案例，平台多行业能力仅作架构说明，不并列推广旅游。截图不得包含真实会话、客服码、凭据与部署地址。功能描述以联合发布后实际可用能力为准。

页脚含文档、后台、隐私、条款、开源与品牌说明；可以说明如何申请试用账号，账号与密码只通过简历或按需发放，官网不公开凭据、不放自动领取入口、不设置假咨询表单。README 双语第一屏、能力与示例主线只讲工业询价，原「在线体验」改为「申请试用账号」（英文使用对应文案），不再链接在线演示。开发者材料可说明平台多行业及旅游回归基线，但不能把旅游作为第二条对外产品主线。

隐私政策与条款使用公开通用模板，服务专属正文由 owner 在私有发布层审定，带版本与生效时间。需覆盖数据类别、AI 处理、保留/删除、备份及用户请求渠道；真实微信隐私告知与同意记录仍走既有机制。没有审定正文不能正式发布，不编造运营主体或联系方式。

正文与链接在脚本失败时仍可用；图片缺失显示文字说明，错误链接有 404 与回首页入口。移动端、键盘与读屏可用；公开站点可索引，后台不可索引。

新增 `docs-site/` 构建入口，内容唯一来源在 `docs/guides/`。只把批准的文件及章节复制到临时源目录，再交 VitePress 构建；本地搜索、站内链接和锚点检查随构建完成。不能把整个 docs 树交给生成器后只隐藏侧栏。六类指南统一以工业询价为使用场景；旅游材料不进入对外导航、搜索和示例主线，已有旅游代码与回归文档留在开发者仓库。

| 快速开始     | 复用 console-access、how-it-works 的使用者路径，以工业询价串联普通账号、扫码与报价；开发者安装另链仓库 |

### R4 · 只读设置与共享权限

侧栏新增「设置」，路由为 `/console/settings/organization`、`/console/settings/members`、`/console/settings/channels`、`/console/settings/usage`，默认组织页。沿用风格 A、主题、字体、StateView、错误映射和懒加载；深链接刷新可恢复。

owner/admin 可读全部设置与新手清单；supervisor/agent/viewer 不显示入口，直达返回无权提示。服务端独立检查：未登录 401，普通成员、沙箱和匿名只读模式 403。共享试用账号是 agent，同样不能进入设置或读取 14 用量，不为它改既有角色含义。官网截图负责展示这些能力。

新增的 HTTP 入口只有下列 GET；URL 均以 `/api/console` 为前缀。DTO、错误码与 query keys 在 `src/shared/console-api.ts` 一处定义，后端和 console 共用；无邀请、改角色、修改组织或渠道写接口。

```ts
interface OrganizationView {
  name: string;
  slug: string;
  packId: string;
  status: 'trial' | 'active' | 'suspended';
  publishedBrandName: string | null;
  pendingBrandChange: boolean;
}
interface MemberView {
  userId: string;
  displayName: string;
  email: string;
  role: 'owner' | 'admin' | 'supervisor' | 'agent' | 'viewer';
  disabled: boolean;
}
interface ChannelView {
  accountId: string | null; // env 来源没有数据库 UUID，不伪造
  key: string; // 租户内业务 key，不当作 accountId
  name: string;
  kind: 'wecom' | 'web';
  source: 'db' | 'env';
  enabled: boolean; // 持久配置，不等同于已装载
  loaded: boolean;
  blockedByProfile: boolean;
  credentialsConfigured: boolean;
  callbackPath: string | null;
  lastInboundAt: string | null;
}
// GET /settings/organization -> OrganizationView
// GET /settings/members -> { items: MemberView[] }
// GET /settings/channels -> { items: ChannelView[] }
// GET /settings/onboarding -> R9 的只读状态
// GET /usage -> 直接使用 14 R9 的 UsageView，不另建设置专用接口
```

身份只来自现有会话与 Host 选出的租户，不接受请求自报 tenantId/role；返回数据不跨租户。查询失败不清成空列表，401 走登录失效，403 不展示旧缓存，其他错误可重试。敏感响应不进入持久浏览器缓存。首批无新的业务表；唯一必要的权限迁移见 R6。

### R5 · 组织只读

展示组织名、标识、行业包、状态与已发布品牌；缺品牌用组织名，不造联系方式。`publishedBrandName` 来自当前发布快照，`pendingBrandChange` 对比待生效品牌，不能把待生效值当线上品牌。平台名「单来」与组织名分层。修改通过平台既有命令与发布流程处理，本期不放保存按钮、不改 SOP 前缀。

### R6 · 成员只读与命令行开通

页面仅展示本租户成员姓名、邮箱、角色与启停状态，支持本地筛选；只有自己时提示「成员由平台开通」，无邀请、改角色、移除或重置密码按钮。开通及变更继续用 `user-create`、`member-role`、`member-remove`、`user-password`、`user-disable`；文档说明联系平台，不让浏览器运行命令。

app 不能直接 SELECT 登录表。新增一个受限读函数 `console_members_read(p_tenant uuid, p_token_hash text)`，仅 agent_app 可执行，固定 search_path、撤销 PUBLIC 执行权；由有效会话 hash、成员关系与当前 owner/admin 权限确定身份，校验租户状态及会话期限，返回 R4 的成员白名单投影，不返回密码 hash、token 或其他组织关系。不接受调用方自称 actor，不授予 app 新的直接表权限。迁移只增加该函数及最小授权，沿用 memberships 的 FORCE RLS；真实 PG 验证伪造租户、过期/降权会话、普通 agent 均不能读取。

### R7 · 渠道只读与维护窗口

展示渠道名称、类型、配置是否启用、启动时是否装载、是否被 profile 禁用、是否配过凭据、回调路径和最近入站时间。运行快照与持久配置分开，配置有行不等于连接成功；没有可靠入站证据时返回 null，不用握手或页面点击伪造已收消息。prod 的 web 渠道显示「当前部署未启用」，没有打开开关。

只显式投影 R4 字段，不能序列化 ChannelAccountRow；不回传密文、密钥编号、企业/客服真实标识、secret、token、AES key 或尾号。完整回调 URL 仅在授权页面由已校验的当前基地址与 callbackPath 组合，不写公开仓库。

### R10 · prod、普通试用账号与手动重置

**线上形态。** 宿主明确设置 `DEPLOY_PROFILE=prod`，只用普通账号密码登录；不新增免密认证端点、特殊登录按钮或在线只读演示。源码 `src/profile.ts` 的 demo 档、模拟器、重置口令、匿名只读、种子保鲜、访客清理及其测试全部保留，AGENTS.md 不变。线上不运行 demo 进程。

**长期停用沙箱。** 复用 [05 plan「长期停用沙箱」](../05-tenancy-sandbox/plan.md)：维护窗口删 sandbox 容器，`.env.sandbox` 改名，持有沙箱进程锁运行现有 `sandbox purge --all`，从反向代理摘沙箱站点；长期不用的体验客服在平台侧停用。宿主去掉旧体验链接配置与对应拨测，部署后确认不再启动该服务。不增加「停止接受新用户」开关；旧沙箱不保留为公开体验，清理失败时入口仍关闭，查明后重试。

**共享试用公司。** 复用现有工业演示租户（standard、工业询价包），不新建另一家公司或改成 sandbox；工业保持非宿主，public_host 改到 app，成为 app 唯一映射的租户。旅游保留 DEFAULT_TENANT_SLUG、宿主身份、env 账号和原 var；按 R12 两段上线后设为 suspended。旅游「保留数据」指不主动清、不做试用清理、不合并或拿来做种子；原保留期和访客清理继续生效，到期数据照常删除，不承诺冻结。工业原数据先盘点为合成数据或试用者自己的消息；正式业务数据混入则停止并报告，不能为了开通试用直接清空。

只有一个发给试用者的普通账号，仅属于试用公司，角色固定为 agent；运维 owner 是单独受控身份，不向试用者发放。普通 agent 的接手、回复、订单权限沿用既有契约，不能修改话术和产品，不称作只读账号。账号与客服码私下按需提供，扫码进入该试用公司的真实企微渠道；不配置真实 ERP 业务连接、不混入其他租户的数据或凭据。

**试用数据与告知。** 数据范围明确为「合成种子 + 试用者自己发的消息」，两者均存本租户 PG；微信消息及标识按真实消息存储，不能冒称全部合成。共享账号可见同一公司的其他试用会话，不承诺 05 沙箱的「只看/只发给本人」隔离。后台页面在试用前显著提示「这是共享试用环境，会话可能被其他试用者看到，请勿发送个人信息」；也可在欢迎语补充，但不写入系统提示词前缀，客户微信文字不用 markdown。告知中说明试用消息的 7 天保留设置和手动重置会清理试用消息；现有隐私说明与同意流程照旧。

用既有 `tenant-retention` 将工业租户的 lead、customer、trace 三项设为 7 天，真实试用消息按既有截止时间与清理任务执行，不写成每条消息发送后恰好第 7 天销毁。**无个人信息的合成种子不参与会话保留期清理**：`readPurgeCandidates` 跳过 state 中 `seed=true` 的会话，避免试用账号 7 天后变空；不延长真实试用消息保留期，不改变 trace 等独立清理规则。手动重置不受此豁免影响，种子与试用者消息一起清理后重建合成基线；不新增定时重置或定时保鲜任务。旅游及其他正式租户的保留期不变。

**种子与重置契约。** 新增可审计的工业询价合成种子清单与平台受控命令 `trial-reset --tenant <slug>`。种子会话 id 为 `trialseed-<批次>-<随机串>`，`channel='simulator'`、`seed=true`，不绑定渠道账号；订单用带批次的随机 id，保持现有长度/字符约束并可按种子来源识别。不使用也不扩展 `isDemoClassId` 的前缀；非宿主无文件后端，种子和真实试用消息都走 PG，旅游 JSON 不参与重置。产品、话术按已有导入/发布路径建立，重置只核对其基线版本，不覆盖配置或新增 standard 整租户删除权。

重置必须满足以下边界，新增 guard 各有自测：

1. 平台侧受控白名单精确绑定现有**非宿主工业** standard 租户 UUID、slug、packId；空名单、不匹配、目标为宿主/沙箱或正式业务数据混入一律拒绝。名称、slug 前缀、status 或命令参数不能代替白名单；旅游和其他正式租户永远不在目标范围。不再绑定专属数据目录或检查合成文件归属，目标业务数据只动 PG。
2. 先停止装载该租户的 app，取得该租户独占锁；完整覆盖清理、写种子和恢复收尾。检查实际共享运行目录中的 spill、恢复哨兵、在途发送和待恢复入站；未处理完不开始重置，也不删除文件绕过。允许清理本租户真实试用消息，不能把「存在真实消息」作为拒绝条件。锁丢失或任何阶段失败保持维护，不开放试用。
3. 两个数据库身份由平台侧编排，**agent_app** 在 `withTenant` 中读取待清清单、经 `writeSeedSessions`（`src/cli/session-transfer.ts`）及现有 repo 写种子、消息 seq 和订单；**agent_platform** 经 `eraseConversation` / `erase_conversation` 逐会话清理，并撤销共享账号会话。不授予 platform 业务表直接 INSERT、不授予 app 新 DELETE，也不把平台凭据放进 app 服务；`import-sessions` 的整目录迁移语义不直接用来追加种子。
4. 两身份操作分阶段，**不能宣称单事务**。使用同一可恢复批次，在 PG 持久记录无客户内容的目标清单、种子版本和阶段进度；承载与读取契约在第 1 步冻结。固定清单后逐项行权删除，再以新批次 id 写入并校验种子；重跑幂等。启动发现本租户未完成批次拒绝对外服务，部分失败不重新开放；完成后重启预载 identity map，验证旧 cookie/合成链接失效。不得从旧 spill 或备份复活已清消息。
5. 行权删除沿用现有范围：消息、trace、同意、附件及关联任务、入站/发送记录；订单去关联留存，既有审计保留，不承诺整库归零或删除交易历史。改密用 user-password 的受控输入，确认共享账号无其他租户成员关系。重置不删除配置版本、审计或用量，不改渠道、密钥、cursor，不清空全局去重/恢复状态；恢复批次记录本身也是无内容的运维记录。
6. 合成会话的人工回复、订单操作走 simulator 路径，不能真实外发；`seed=true` 会话还须在顾问通知入口被确定性拒绝，包含报价、转人工和写入失败通知，不因标准租户身份落入通知群。以外发记录器验证企微客户发送与顾问通知均为零；真实试用微信消息仍按标准链路收发。工作台用 `seed=true` 识别来源，不排除新 id；正常消息 append-only，删除只经既有受限路径，验证旅游及另一正式租户不受重置影响。
