## 目标与非目标

目标：官网用合成截图解释产品；文档提供六类使用指南；后台增加只读组织、成员、渠道与 14 用量页及新手清单；线上 prod、普通登录、一个共享试用账号；完成新旧地址切换和回退设计。

非目标：网页邀请、角色修改、网页提交渠道、渠道热重载、在线修改组织；统一 SaaS 身份或自助注册；开通购买流程、自动收款、ERP 设置界面；后台视觉重做、模型或 SOP/护栏调整；prod 解禁网页渠道；仓库改名。商业内容另记。此次仅修订文档，不写实现、不改关联文件、不操作服务器、不提交。

## 现状与方案

### R1 · 三个入口与静态托管

完整地址通过私有发布配置注入，公开文档只写子域职责。

| 子域   | 用途                               | 边界                                                                               |
| ------ | ---------------------------------- | ---------------------------------------------------------------------------------- |
| `www`  | 官网、能力、截图、隐私、条款与页脚 | 现有 Caddy 服务静态构建产物；不读成员 cookie、不请求租户 API                       |
| `app`  | 正式登录及 `/console/` 后台        | 现有 Node 服务，经 Caddy；只映射一个明确的 standard 租户，试用公司映射见待确认事项 |
| `docs` | 使用者文档                         | 同一 Caddy 的独立静态根；不发布架构、计划及运维材料                                |

静态站选现有 Caddy：复用发布链，代价是共用服务器故障域；曾比较 Pages，独立发布有益但增加部署配置，后续仍可迁移相同产物。文档采用 VitePress，固定版本与锁文件，独立于 console 运行依赖。选型在 ready 时登记 ADR，不在本轮多写文件。

静态根只指构建产物；私有品牌、法律正文、实际地址与账号在仓库外组装。公开构建可用明确占位，正式发布检查拒绝缺项。后台沿用同源检查、CSP、no-store 与 Host-only cookie，不放宽跨源租户 API；新域首次登录，不能靠扩大 cookie Domain 迁移会话。未知 Host 在代理层拒绝，避免单租户时应用的默认 Host 回落成为公开入口。

### R2 · 官网与申请试用

拟新增静态源码 `site/`，不塞入客户页面目录 `public/`。固定页面 `/`、`/product/`、`/privacy/`、`/terms/`。首页展示「单来」、一句话能力、合成产品截图、接待到人工接手的流程、文档与后台入口；不登录也能看懂。截图不得包含真实会话、客服码、凭据与部署地址。功能描述以联合发布后实际可用能力为准。

页脚含文档、后台、隐私、条款、开源与品牌说明；可以说明如何申请试用账号，账号与密码只通过简历或按需发放，官网不公开凭据、不放自动领取入口、不设置假咨询表单。README 双语第一屏介绍产品，原「在线体验」改为「申请试用账号」（英文使用对应文案），不再链接在线演示。

隐私政策与条款使用公开通用模板，服务专属正文由 owner 在私有发布层审定，带版本与生效时间。需覆盖数据类别、AI 处理、保留/删除、备份及用户请求渠道；真实微信隐私告知与同意记录仍走既有机制。没有审定正文不能正式发布，不编造运营主体或联系方式。

正文与链接在脚本失败时仍可用；图片缺失显示文字说明，错误链接有 404 与回首页入口。移动端、键盘与读屏可用；公开站点可索引，后台不可索引。

### R3 · 文档站

拟新增 `docs-site/` 构建入口，内容唯一来源在 `docs/guides/`。只把批准的文件及章节复制到临时源目录，再交 VitePress 构建；本地搜索、站内链接和锚点检查随构建完成。不能把整个 docs 树交给生成器后只隐藏侧栏。

HTML、搜索索引、站点地图、资源与源码映射不得含 spec、plan、ADR、架构/功能设计目录、运维手册及私有内容。指南中连向设计文档的链接改为使用说明或明确的公开仓库开发者链接。空搜索给清除入口，搜索加载失败可重试且正文仍可读；无发布记录时如实说明。

### R4 · 只读设置与共享权限

侧栏新增「设置」，路由为 `/console/settings/organization`、`/console/settings/members`、`/console/settings/channels`、`/console/settings/usage`，默认组织页。沿用风格 A、主题、字体、StateView、错误映射和懒加载；深链接刷新可恢复。

owner/admin 可读全部设置与新手清单；supervisor/agent/viewer 不显示入口，直达返回无权提示。服务端独立检查：未登录 401，普通成员、沙箱和匿名只读模式 403。共享试用账号是 agent，同样不能进入设置或读取 14 用量，不为它改既有角色含义。官网截图负责展示这些能力。

拟新增的 HTTP 入口只有下列 GET；URL 均以 `/api/console` 为前缀。DTO、错误码与 query keys 在 `src/shared/console-api.ts` 一处定义，后端和 console 共用；无邀请、改角色、修改组织或渠道写接口。

```ts
interface OrganizationView {
  name: string;
  slug: string;
  packId: string;
  status: 'trial' | 'active' | 'suspended';
  publishedBrandName: string | null;
  pendingBrandChange: boolean;
}
interface MemberView {
  userId: string;
  displayName: string;
  email: string;
  role: 'owner' | 'admin' | 'supervisor' | 'agent' | 'viewer';
  disabled: boolean;
}
interface ChannelView {
  accountId: string | null; // env 来源没有数据库 UUID，不伪造
  key: string; // 租户内业务 key，不当作 accountId
  name: string;
  kind: 'wecom' | 'web';
  source: 'db' | 'env';
  enabled: boolean; // 持久配置，不等同于已装载
  loaded: boolean;
  blockedByProfile: boolean;
  credentialsConfigured: boolean;
  callbackPath: string | null;
  lastInboundAt: string | null;
}
// GET /settings/organization -> OrganizationView
// GET /settings/members -> { items: MemberView[] }
// GET /settings/channels -> { items: ChannelView[] }
// GET /settings/onboarding -> R9 的只读状态
// GET /usage -> 直接使用 14 R9 的 UsageView，不另建设置专用接口
```

身份只来自现有会话与 Host 选出的租户，不接受请求自报 tenantId/role；返回数据不跨租户。查询失败不清成空列表，401 走登录失效，403 不展示旧缓存，其他错误可重试。敏感响应不进入持久浏览器缓存。首批无新的业务表；唯一必要的权限迁移见 R6。

### R5 · 组织只读

展示组织名、标识、行业包、状态与已发布品牌；缺品牌用组织名，不造联系方式。`publishedBrandName` 来自当前发布快照，`pendingBrandChange` 对比待生效品牌，不能把待生效值当线上品牌。平台名「单来」与组织名分层。修改通过平台既有命令与发布流程处理，本期不放保存按钮、不改 SOP 前缀。

### R6 · 成员只读与命令行开通

页面仅展示本租户成员姓名、邮箱、角色与启停状态，支持本地筛选；只有自己时提示「成员由平台开通」，无邀请、改角色、移除或重置密码按钮。开通及变更继续用 `user-create`、`member-role`、`member-remove`、`user-password`、`user-disable`；文档说明联系平台，不让浏览器运行命令。

app 不能直接 SELECT 登录表。拟新增一个受限读函数 `console_members_read(p_tenant uuid, p_token_hash text)`，仅 agent_app 可执行，固定 search_path、撤销 PUBLIC 执行权；由有效会话 hash、成员关系与当前 owner/admin 权限确定身份，校验租户状态及会话期限，返回 R4 的成员白名单投影，不返回密码 hash、token 或其他组织关系。不接受调用方自称 actor，不授予 app 新的直接表权限。迁移只增加该函数及最小授权，沿用 memberships 的 FORCE RLS；真实 PG 验证伪造租户、过期/降权会话、普通 agent 均不能读取。

### R7 · 渠道只读与维护窗口

展示渠道名称、类型、配置是否启用、启动时是否装载、是否被 profile 禁用、是否配过凭据、回调路径和最近入站时间。运行快照与持久配置分开，配置有行不等于连接成功；没有可靠入站证据时返回 null，不用握手或页面点击伪造已收消息。prod 的 web 渠道显示「当前部署未启用」，没有打开开关。

只显式投影 R4 字段，不能序列化 ChannelAccountRow；不回传密文、密钥编号、企业/客服真实标识、secret、token、AES key 或尾号。完整回调 URL 仅在授权页面由已校验的当前基地址与 callbackPath 组合，不写公开仓库。

新增、更换凭据、启停及已有 env 账号导入继续走 `channel-account`、`channel-import` 等现有 CLI：取租户独占锁，在维护窗口应用、重启装载，再验证回调和真实消息。页面没有凭据表单、保存、申请状态或重启按钮；渠道网页提交只在「后续」保留设计要点。

### R8 · 用量最后接入 14 R9

直接使用 `GET /api/console/usage`：status、month、`replies.used/quota`、`daily.costMilli/capMilli`、`days[].day/replies/costMilli`。不重复实现计数、月界、费用或额度 API；金额换算采用 14 与既有用量模块的单位。展示本月回复、上限、当日用量及本月曲线/表格，注明模型用量统计不是服务账单。

null 表示不限，0 表示上限为零，不除零；空 days 显示本月暂无用量。达到上限展示原因与联系管理员，不放购买、充值、调额度按钮。首次加载骨架，失败保留旧值并标未更新；页面打开、聚焦和可见期间每 30 秒重取，隐藏时暂停。401/403 沿用真实鉴权，不能以假数据补权限或实现缺口。

14 R9 尚未实现；本页是第 1 批最后一个实现步骤，必须等其他界面及 14 R9 合入，再接真实接口、真实计数。普通试用 agent 不为体验此页而提权。

### R9 · 新手引导与三种状态

owner/admin 登录后在总览显示可收起清单。拟新增 `GET /settings/onboarding -> { steps: { key, state: 'todo' | 'done' | 'blocked', href, reason? }[] }`；key 为 team/catalog/sop/channel，href 只允许批准的同源页面。完成状态来自当前事实：team 有另一位有效成员；catalog 按行业包有可用上架条目；sop 有已发布版本；channel 有实际装载的企微账号及真实入站记录。点击链接、保存草稿或仅通过回调握手都不算完成。

team/channel 链接到只读设置与平台协助说明；catalog/sop 链接现有编辑页面。仅一名成员也允许继续使用。配置由 CLI 改动后重新打开/聚焦重取；需要重启的状态如实显示。收起偏好仅本地保存。普通顾问只有与其工作相关的说明，不显示配置清单或管理员操作入口。

### R10 · prod、普通试用账号与手动重置

**线上形态。** 宿主明确设置 `DEPLOY_PROFILE=prod`，只用普通账号密码登录；不新增免密认证端点、特殊登录按钮或在线只读演示。源码 `src/profile.ts` 的 demo 档、模拟器、重置口令、匿名只读、种子保鲜、访客清理及其测试全部保留，AGENTS.md 不变。线上不运行 demo 进程。

**长期停用沙箱。** 复用 [05 plan「长期停用沙箱」](../05-tenancy-sandbox/plan.md)：维护窗口删 sandbox 容器，`.env.sandbox` 改名，持有沙箱进程锁运行现有 `sandbox purge --all`，从反向代理摘沙箱站点；长期不用的体验客服在平台侧停用。宿主去掉旧体验链接配置与对应拨测，部署后确认不再启动该服务。不增加「停止接受新用户」开关；旧沙箱不保留为公开体验，清理失败时入口仍关闭，查明后重试。

**共享试用公司。** 只有一个发给试用者的普通账号，仅属于独立的 standard 试用租户，角色固定为 agent；运维 owner 是单独受控身份，不向试用者发放。产品、话术与会话基线全部合成；不复制现有两个租户的真实会话、订单、渠道或凭据，不配置真实 ERP 业务连接。普通 agent 的接手、回复、订单权限沿用既有契约，不能称作只读账号，不能修改话术和产品。账号与客服码通过私有材料按需提供；扫码体验必须走真实微信客服，不能退回网页聊天。真实微信数据归属与共享可见性的矛盾见需要确认的问题 1，未解决不接到共享租户。

**合成种子与重置契约。** 新增可审计的合成种子清单与一条平台命令 `trial-reset --tenant <slug>`，只恢复该试用公司的合成会话和合成订单；初始产品、话术通过已有配置导入/发布路径建立，重置只校验其基线版本，不绕过发布流程覆盖配置。不做定时任务。

当前最小可行方案是试用公司作为宿主，复用已有 JSON 合成会话后端（`wecom:cust_` 类），种子不进入真实消息表，不新增 standard 租户整库清除权限。只有宿主支持此后端；选用哪个行业包及是否切宿主必须按需要确认的问题 2 定案，不能让实现者默选。非宿主 PG 种子或把真实消息一起清空均需先补设计，本稿不授权。

重置必须满足以下边界，新增 guard 各有自测：

1. 白名单由平台侧受控配置提供，精确绑定 tenant UUID、slug、packId 与专属数据目录；名称、slug 前缀、`status=trial` 或调用者参数都不能代替白名单。空名单、非 standard、不匹配、目录越界/符号链接、非当前宿主一律拒绝。只允许指定目标，不能批量遍历正式租户。
2. 先停装载该租户的 app 并取得其独占锁，核对无未回放 spill、无真实会话/真实订单混入、无未完成发送，且全部种子引用属于批准清单。文件后端本身不带 tenant_id，必须另有与白名单一致的归属清单；缺失时拒绝，不能把旧宿主 var 当作试用目录。正式租户的文件和 PG 行均不能被覆盖或删除。
3. 在同目录暂存并校验两份文件，用恢复标记与原子替换保证会话/订单版本一致；失败保留维护状态，启动检测未完成标记时拒绝装载，重跑可恢复，不能自动重启半份数据。轮换批次 id，作废旧合成订单链接，保留不含内容的重置审计。
4. 撤销共享账号会话；需要轮换密码时走既有 `user-password`，受控输入，不出现在命令行参数、输出或仓库。确认该账号没有其他租户成员关系。重置不删除审计、配置版本、用量账本，不改渠道、密钥、cursor 或幂等记录；不会把额度清零。
5. 合成会话的人工动作不得产生真实企微发送；以记录外发请求的传输替身验证。发现现有发送分支不能保证这一点时，先补确定性 guard 与自测，不接真实凭据进行试探。正式客户消息仍遵守 append-only 与现有行权删除规则。

## 需要确认的问题

这些是源码核对后发现的实现约束，区别于已定的十项产品选择；不得借此恢复旧演示方案。三项在 ready 前补定，实际值私下登记。

1. **真实扫码与「只有合成数据」如何同时满足？** 微信入站会持久化真实访客标识和消息，普通 agent 可看本租户会话并向其负责的客户回复。若扫码进入同一个共享试用公司，就不再只有合成数据，也不具备 05「只发给本人」隔离。推荐试用公司只放合成数据，扫码走独立的受控正式客服租户，共享账号无该租户成员关系；代价是试用者不能在共享后台看到自己的微信会话。另一选项是 owner 明确接受试用参与者聊天互见、规定告知与清理范围，再修订本稿的数据约束；不能默认为已获同意。
2. **试用公司映射及旧两个租户如何安置？** 现有合成 JSON 仅宿主可装载，prod 不会隔离旧 var；两个旧租户已有的真实渠道、消息与有效链接本次未查看。推荐新试用公司做 app 唯一映射及宿主，绑定独立合成数据目录，选定复用的行业包；旧租户有真实业务则保留原归属与兼容入口，无业务则归档后退役。必须先确认原宿主回调、env 账号、spill/恢复标记能安全迁移。若 app/宿主必须保留现有正式租户，需要补非宿主合成种子的存储与重置契约，不能直接套现有 JSON；这是 ready 前的架构阻塞。
3. **prod 支付外观的旧字节契约如何收窄？** `public/pay.html` 仍带演示提示，而 [08](../08-pack-generalization/spec.md) 不变量 4 与 `src/payment/legacy-bytes.selftest.ts:4` 固定了旧旅游单 online/advisor 的完整 HTML 字节。推荐只部分取代 prod/advisor 支付页的演示文案/平台外观字节约束，保留 demo、金额、状态、公开 JSON、付款卡片、订单卡与锁定套件不变，并为新 prod 输出建立明确基线；需在批准 ready 前将准确取代范围补到顶部及 08 反向标注。若坚持所有旧字节不变，线上无演示文案与保留旧支付链接无法同时达成；不能用代理改正文或跳过自测掩盖。
