# 生产化路径（当前实现与后续边界）

本文从 README 搬来（2026-10-27），按 07–10 更新。路线以 [架构总参考](../architecture/master-reference.md) 与 [02 上线清单](../architecture/02-conversations-workbench/plan.md#上线清单接第一个真实租户之前) 为准。01 已引入 Postgres 配置、SOP 版本与成员后台，02 已实现数据库会话、追加消息、发送账本、持久任务与顾问收款，03 把企微入站与 cursor 搬进 `channel_inbox` 并按账号拆开运行时，04 抽出行业包，05 实现同部署多租户与一键体验沙箱，06 补上回复的出口检查与真实模型回归，07 把政策收成单一来源并加上知识库与售后退改，08 把核心去旅游化（产品种类、通用订单与金额），09 加上报价审批、报价单页与按包登记的站内链接，10 做了第二个公开参考包「工业品询价」并在同一部署里开了演示租户。09、10 已随 `demo-v10-rc2` 上线演示环境，正在收尾翻 `implemented`。不能再以「无数据库、定期全量 JSON」描述所有运行模式。

| 状态或能力                   | 当前实现                                                                                                                                                                                                                                     | 后续边界                                                             |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| 会话、消息、订单             | DB 存储落 Postgres，启动预载 identity map；文件模式与 demo 类仍用 JSON                                                                                                                                                                       | 多副本需 fence、会话锁与 identity map 协调（阶段 8，按信号）         |
| 配置与租户                   | 按租户隔离（FORCE RLS + 进程内状态登记）；宿主进程装 standard 租户，多个时严格按 Host（`public_host`）解析，演示环境现有旅游与工业品询价两个演示租户；沙箱进程同时托管多个临时租户，从模板开通、整租户删除；已登记旅游与工业品询价两个行业包 | standard 租户的模板开通与整租户删除；电商售后参考包等其余阶段 8 候选 |
| 聊天、查询、登录、预算限流   | 有进程内限额与有界计数，部分预算状态本地持久化                                                                                                                                                                                               | 多副本前必须统一跨进程计数；当前未用 Redis                           |
| 同会话串行与租户锁           | 引擎进程内串行，DB 配置租户锁阻止第二个进程                                                                                                                                                                                                  | 分布式会话互斥与选主（阶段 8，按信号）                               |
| 企微 cursor / 入站 / 去重    | DB 存储下入站记录与去重在 `channel_inbox`，cursor 与入站同一事务推进，出站分段发送前入库；文件存储仍用 JSON cursor 与在途表                                                                                                                  | 多副本时企微拉取选主（阶段 8，按信号）                               |
| 跟进、转人工通知、保留期清理 | DB 模式由 `jobs` 驱动、认领与重试；文件模式跟进保留扫描器                                                                                                                                                                                    | 不需要为已实现的延迟任务再引入 BullMQ；任务量与运维需求变化时再评估  |
| 部署与观测                   | 宿主与体验沙箱两个服务（同一镜像、各单副本）的 Compose、健康检查与受限回滚、加密备份、主机巡检、外部拨测、运行数字、11 类告警及可选 OTel                                                                                                     | 多副本滚动更新（阶段 8，按信号）；OTel 接收端（如 Langfuse）按需部署 |

Postgres 已提供持久化、事务与权限边界，但不能替代仍在内存的并发协调。只有需要多副本时才评估 Redis 等跨进程状态设施；当前不引入它。市场、定价、客户与主体相关事项另记，不在公共仓库中展开。
